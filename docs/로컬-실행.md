# 로컬 실행 안내

작성일 2026-11-04

AWS(EC2 · RDS · S3)를 내린 뒤에도 내 맥에서 앱 전체를 돌리는 방법입니다.

---

## 0. 먼저 결론

| 예전 (AWS) | 지금 (로컬) |
| --- | --- |
| EC2 에서 backend · ai · celery | 내 맥의 도커 (`--profile app`) |
| RDS (PostgreSQL 17) | 도커 `postgres` (pgvector:pg17) |
| S3 버킷 `gooddeedquest-prod` | 도커 `s3` (VersityGW, S3 와 말하는 방식이 같음) |

**코드는 거의 그대로입니다.** boto3 가 붙는 주소만 AWS 에서 `localhost:9000` 으로 바뀌었습니다.
`.env` 에 `S3_ENDPOINT_URL` 을 지우면 다시 AWS 로 붙습니다.

---

## 1. 처음 한 번만

### 1-1. `.env` 의 S3 부분 바꾸기

저장소 최상위 `.env` 에서 `# AWS S3` 아래를 이렇게 바꿉니다. 나머지(OpenAI · Gemini 키 등)는 그대로 둡니다.

```
AWS_REGION=ap-northeast-2
AWS_ACCESS_KEY_ID=gooddeed
AWS_SECRET_ACCESS_KEY=gooddeed123
S3_BUCKET_NAME=gooddeedquest-prod
S3_ENDPOINT_URL=http://localhost:9000
```

이 키는 AWS 키가 아니라 `docker-compose.yml` 의 로컬 S3 에 적힌 값입니다. 로컬 전용이라 비밀이 아닙니다.
**예전 AWS 키는 지워도 됩니다.** 서버를 내리면 쓸 데가 없습니다.

### 1-2. 백업 파일 두기

서버에서 받아둔 백업이 저장소 최상위에 있어야 합니다. (`.gitignore` 에 들어 있어서 git 에는 안 올라갑니다.)

```
GoodDeedQuest/
├── s3-backup/      ← S3 버킷을 통째로 받은 것 (bgm, community, profile, shortform, submission)
└── gdq-dump.sql    ← RDS 덤프
```

**이 두 개가 서비스 데이터의 유일한 사본입니다.** 외장 디스크나 구글 드라이브에도 한 벌 복사해 두세요.

### 1-3. DB 복원 (이미 했다면 건너뜀)

로컬 DB 에 이미 데이터가 있는지 먼저 봅니다.

```bash
docker compose up -d postgres
```

```bash
docker compose exec -T postgres psql -U gooddeed -d gooddeedquest -c "SELECT count(*) FROM community_post;"
```

`1154` 가 나오면 복원이 끝난 상태입니다. 테이블이 없다고 나오면 아래 두 줄을 실행합니다.

```bash
docker compose exec -T postgres psql -U gooddeed -d gooddeedquest -c "CREATE EXTENSION IF NOT EXISTS vector;"
```

```bash
docker compose exec -T postgres psql -U gooddeed -d gooddeedquest < gdq-dump.sql
```

## 2. 매일 쓰는 방법

### 2-1. 전부 도커로 (추천)

```bash
docker compose --profile app up -d --build
```

이거 하나로 DB · Redis · S3 · backend(8000) · ai(8001) · celery 셋이 다 뜹니다.
처음 뜰 때 `s3-init` 이 `s3-backup/` 을 로컬 S3 에 채웁니다. 이미 있는 파일은 건너뜁니다.

### 2-2. 서버는 내 터미널에서

코드를 고치면서 바로 보고 싶을 때입니다. 도커로는 DB · Redis · S3 만 띄웁니다.

```bash
docker compose up -d
```

```bash
python -m backend.main
```

```bash
python -m ai.main
```

반드시 **저장소 최상위 폴더**에서 실행하세요.

### 2-3. 앱 (Expo 개발 빌드)

```bash
cd frontend && npx expo start --dev-client
```

앱은 Metro 주소를 따라 **내 맥의 백엔드**를 봅니다 (`frontend/src/api/client.ts`).
폰과 맥이 **같은 와이파이**에 있어야 합니다.

## 3. 사진·영상 주소는 어떻게 맞춰지나

앱은 사진을 S3 에 직접 올리고 직접 받습니다. 백엔드는 그때 쓸 **서명된 주소(presigned URL)** 만 내려줍니다.

여기서 문제가 하나 있습니다. 서버 입장에서 S3 는 `localhost:9000` 인데,
**폰에서 `localhost` 는 폰 자기 자신**입니다. 폰은 맥의 IP 로 와야 합니다.

그래서 백엔드는 **앱이 접속해 온 주소**를 그대로 씁니다.

```
폰이 http://192.168.0.10:8000 으로 요청 → 사진 주소를 http://192.168.0.10:9000/... 으로 내려줌
에뮬레이터가 http://10.0.2.2:8000 으로 요청 → http://10.0.2.2:9000/...
```

와이파이를 바꿔 맥 IP 가 바뀌어도 설정을 고칠 필요가 없습니다.
주소를 고정하고 싶으면 `.env` 에 `S3_PUBLIC_ENDPOINT_URL=http://<주소>:9000` 을 적으면 그게 이깁니다.

서버끼리 주고받는 주소(backend → ai 인증 판정)는 항상 안쪽 주소로 만듭니다
(`generate_internal_download_url`).

## 5. 조심할 것

```bash
docker compose down -v
```

**DB 와 로컬 S3 를 둘 다 지웁니다.** 되돌리려면 1-3 의 복원을 다시 하고, `docker compose up -d` 로
`s3-init` 이 백업을 다시 채우게 해야 합니다. `s3-backup/` 과 `gdq-dump.sql` 이 없으면 영영 못 되돌립니다.

**앱에서 새로 올린 사진은 로컬 S3 에만 있습니다.** `s3-backup/` 에는 안 들어갑니다.

`docker-compose.yml` 맨 위에 `name: gooddeedquest` 를 적어 두었습니다.
그래서 git worktree 처럼 다른 폴더에서 띄워도 **같은 DB 볼륨**을 씁니다.

---

## 6. 왜 MinIO 가 아닌가

로컬 S3 로 흔히 쓰는 건 MinIO 인데, **MinIO 가 Docker Hub 에서 이미지를 내려서** 받을 수가 없습니다.
그래서 VersityGW(Apache 2.0)를 씁니다. boto3 입장에서는 둘 다 똑같은 S3 입니다.
