# 1단계. GitHub Actions 배포 차단

- [ ] `deploy.yml` 의 `on:` 수정
- [ ] dev 에 푸시해서 배포가 안 도는지 확인

**왜 먼저 하나**: 작업 도중 누가 `dev` 에 머지하면 서버가 다시 배포돼서 꼬입니다.

CI 검증과 `main` 자동 병합은 **그대로 둡니다.** 배포만 막습니다.

`.github/workflows/deploy.yml` 의 맨 위만 바꿉니다.

```yaml
name: Deploy to EC2

# ============================================================
# 【2026-09-07 비활성화】
# 프로젝트 종료로 EC2/RDS 를 정리하면서 자동 배포를 껐다.
# 아래 push 트리거만 주석 처리했고, 배포 절차 자체는 그대로 남겨둔다.
#
# 다시 켜려면 주석 세 줄을 되살리고, 아래 시크릿을 다시 등록하면 된다.
#   DOCKERHUB_USERNAME / DOCKERHUB_TOKEN / EC2_HOST / EC2_SSH_KEY
#
# 동작 방식:
#   main 에 푸시 → amd64 이미지 빌드 → Docker Hub 푸시
#   → EC2 에 SSH 접속 → docker compose pull && up -d
# ============================================================
on:
  # push:
  #   branches: [main]
  workflow_dispatch:
```

`ci-dev.yml` 은 **손대지 않습니다.**

바꾼 뒤 흐름은 이렇게 됩니다.

```
dev 머지 → CI 검증 → main 자동 병합 → (여기서 멈춤)
```

`workflow_dispatch` 를 남긴 이유는 Actions 탭에 워크플로우가 계속 보이게 하려는 것입니다.
목록에서 사라지면 자동 배포를 구현했다는 기록도 같이 안 보입니다.

받은 뒤 반드시 확인하세요.

# 5단계. 서버 DB → 로컬

- [ ] Docker Desktop 켜기

- [ ] 로컬 DB 세우고 확장 만들기
- [ ] 복원
- [ ] 테이블·건수 확인

로컬에 `pg_dump` 가 없으므로 도커로 대신합니다.

### 5-1. 로컬 DB 완전 초기화

```bash
docker compose down -v
```

### 5-2. SSH 터널 열기

RDS 는 EC2 에서만 접근됩니다. EC2 를 통로로 씁니다.
**이 창은 켜둔 채로** 두세요. 닫으면 터널이 끊깁니다.

```bash
ssh -i ~/.ssh/<키파일>.pem -N -L 55432:<RDS엔드포인트>:5432 ubuntu@<탄력적IP>
```

로컬 도커 postgres 가 5432 를 쓰기 때문에 터널은 55432 로 뺐습니다.

### 5-3. 덤프 뜨기

**새 터미널**에서 실행합니다.

```bash
docker run --rm -v "$PWD":/out pgvector/pgvector:pg17 pg_dump -h host.docker.internal -p 55432 -U <디비유저> -d <디비이름> --no-owner --no-acl -f /out/gdq-dump.sql
```

`pgvector/pgvector:pg17` 이미지를 쓰는 이유는 **RDS 가 PostgreSQL 17** 이기 때문입니다.
pg_dump 버전이 서버보다 낮으면 거부당합니다.

비밀번호를 물어봅니다. **채팅이나 문서에 붙여넣지 마세요.**

끝나면 크기를 확인하세요. **0 바이트면 실패한 것입니다.**

```bash
ls -lh gdq-dump.sql
```

### 5-4. 로컬 DB 세우기

```bash
docker compose up -d
```

### 5-5. 확장 먼저 만들기

임베딩 컬럼이 `vector` 타입이라 확장이 먼저 있어야 복원이 됩니다.

```bash
docker compose exec -T postgres psql -U gooddeed -d gooddeedquest -c "CREATE EXTENSION IF NOT EXISTS vector;"
```

### 5-6. 복원

```bash
docker compose exec -T postgres psql -U gooddeed -d gooddeedquest < gdq-dump.sql
```

### 5-7. 확인

```bash
docker compose exec -T postgres psql -U gooddeed -d gooddeedquest -c "\dt"
```

```bash
docker compose exec -T postgres psql -U gooddeed -d gooddeedquest -c "SELECT count(*) FROM volunteer_center;"
```

# 7단계. Expo 로컬 개발 복구

- [ ] 개발 빌드 설치

### Expo Go 로는 되돌릴 수 없습니다

**EAS 빌드 때문에 깨진 게 아닙니다.** 처음부터 안 되는 구조였습니다.

Expo Go 는 미리 만들어진 앱이라, 그 안에 들어 있는 네이티브 기능만 쓸 수 있습니다.
그런데 우리 앱은 두 개를 씁니다.

```
@react-native-seoul/kakao-login        Expo Go 안에 없음
@react-native-google-signin/...        Expo Go 안에 없음
```

카카오 로그인은 자바·코틀린으로 짜인 **네이티브 코드**입니다.
자바스크립트만 갈아끼우는 Expo Go 로는 넣을 수 없습니다.
첫 화면이 로그인이라 켜자마자 막힙니다.

### 대신 개발 빌드를 씁니다

**우리 네이티브 모듈이 들어간 나만의 Expo Go** 라고 보시면 됩니다.
한 번 설치하면 그 뒤로는 Expo Go 와 똑같이 씁니다. 코드를 고치면 바로 반영됩니다.

준비는 이미 다 돼 있습니다.

```
expo-dev-client ~6.0.21    설치됨
android/ 폴더               있음 (prebuild 완료)
```

**방법 (a) — 내 맥에서 직접 빌드.** Android Studio 가 있으면 이게 빠릅니다.

```bash
cd frontend && npx expo run:android
```

**방법 (b) — 클라우드 빌드.** Android Studio 가 없으면 이쪽입니다. 15~30분 걸립니다.

```bash
cd frontend && npx eas-cli build --profile development -p android
```

### 설치 후 매일 쓰는 방법

```bash
cd frontend && npx expo start --dev-client
```

`--dev-client` 를 빼면 Expo Go 로 열려고 해서 또 막힙니다.

### 서버를 내려도 로컬은 안 깨집니다

`frontend/.env` 에 `EXPO_PUBLIC_API_URL` 이 **없습니다.** 카카오 키만 있습니다.

`src/api/client.ts:26` 의 판단 순서를 보면 이렇게 됩니다.

```
① EXPO_PUBLIC_API_URL   → 없음. 넘어감
② Metro 의 hostUri      → 여기서 잡힘. http://<맥IP>:8000/api/v1
③ app.json extra.apiUrl → 도달하지 않음
```

**개발 중에는 항상 ②로 떨어져서 내 맥의 백엔드를 봅니다.** 배포 서버와 무관합니다.

# 8단계. ⚠️ 서버 내리기

- [ ] S3 비우고 삭제

### 8-1. EC2 종료

EC2 → 인스턴스 선택 → **인스턴스 상태 → 인스턴스 종료(Terminate)**

"중지(Stop)" 가 아니라 **종료(Terminate)** 입니다. 중지는 EBS 요금이 계속 나갑니다.

### 8-2. ★ 탄력적 IP 반납

EC2 → **탄력적 IP** → 선택 → **작업 → 탄력적 IP 주소 릴리스**

**이걸 빼먹으면 서버가 없어도 계속 과금됩니다.**
서버에 붙어 있을 때는 무료인데 떼어지면 유료라, EC2 를 지운 순간부터 돈이 나갑니다.

### 8-3. EBS 볼륨 확인

EC2 → **볼륨** → 상태가 `available`(어디에도 안 붙음)인 게 있으면 삭제합니다.

인스턴스를 종료하면 루트 볼륨은 보통 같이 지워지지만, 눈으로 확인해야 합니다.

### 8-4. RDS 삭제

RDS → 데이터베이스 선택 → **작업 → 삭제**

- **"최종 스냅샷 생성" 체크 해제** ← 체크하면 스냅샷이 남아 계속 과금됩니다
- **"자동 백업 보존" 체크 해제**

이미 로컬에 덤프를 떴으니 스냅샷은 필요 없습니다.

### 8-5. RDS 스냅샷 정리

RDS → **스냅샷** → 남아 있는 것 전부 삭제. 자동 백업이 만든 것도 있습니다.

### 8-6. S3 비우고 삭제

**4단계 백업을 확인한 뒤에** 합니다.

S3 → 버킷 선택 → **비우기(Empty)** → 그다음 **삭제(Delete)**

비우지 않으면 삭제가 안 됩니다.

### 8-7. 보안 그룹 정리

EC2 → **보안 그룹** → `gdq-ec2-sg`, `gdq-rds-sg` 및 안 쓰는 것 삭제.

서로를 참조하고 있으면 삭제가 거부됩니다. **참조 규칙을 먼저 지우고** 그룹을 지우세요.

### 8-8. IAM 정리

IAM → **역할** → EC2 에 붙였던 S3 접근 역할 삭제
IAM → **정책** → 직접 만든 정책이 있으면 삭제

### 8-9. 선택 사항

**Docker Hub 이미지** (`leochoi224/gooddeedquest`) — 무료 계정이면 그냥 둬도 됩니다.
배포 파이프라인의 증거로 남겨두는 것도 괜찮습니다.

**DuckDNS 도메인** — 무료라 유지 비용이 없습니다.
다만 서버가 없으면 접속이 안 되니, 포트폴리오에 링크를 걸지 마세요.

**★ 비공개 테스트 20명 × 14일** — 2023년 11월 이후 만든 **개인** 개발자 계정은,
프로덕션 출시 전에 테스터 20명을 모아 **14일 연속** 비공개 테스트를 돌려야 합니다.
20명이 실제로 옵트인해야 하고, 14일 중 하루라도 인원이 20명 밑으로 떨어지면
카운터가 처음부터 다시 셉니다. **실질적으로 가장 큰 장벽입니다.**

**콘텐츠 등급 설문** · **데이터 안전 섹션** — 어떤 개인정보를 수집해 어디에 쓰는지 신고합니다.
우리 앱은 위치·사진·계정 정보를 쓰므로 항목이 꽤 됩니다.

**★ 개인정보처리방침 URL** — 필수이고, 실제로 열리는 웹페이지여야 합니다.
**서버를 내리면 이 URL 도 죽습니다.** GitHub Pages 같은 무료 호스팅에 따로 올려야 합니다.

## 빌드

**AAB 형식** — 스토어는 APK 를 받지 않습니다.
`eas build --profile production` 이 AAB 를 만듭니다. `eas.json` 에 프로필이 이미 있습니다.

**타겟 API 레벨** — Play 는 매년 최소 요구 수준을 올립니다.
Expo SDK 54 라 현재는 맞지만, 업데이트 없이 1년 두면 신규 설치가 막힙니다.

**앱 서명** — Play App Signing 에 키를 맡깁니다. EAS 가 만든 키를 업로드하면 됩니다.

## ★ 우리 프로젝트가 지금 상태로 걸리는 것

**`usesCleartextTraffic: true`** (`app.json:59`)
암호화 안 된 http 통신을 허용한다는 설정입니다. 로컬 개발 때문에 켰는데
**심사에서 지적받을 수 있고 보안 경고가 붙습니다.**
출시하려면 꺼야 하고, 끄면 개발 빌드가 로컬 서버에 못 붙습니다. 프로필을 나눠야 합니다.

**카카오 앱 키가 소스에 평문** (`app.json:39`)

**서버를 계속 켜둬야 합니다**
앱이 서버 없이는 아무것도 못 합니다. 출시하려면 EC2 와 RDS 를 상시 운영해야 하고,
`t3.small` + RDS 조합이면 **월 5만 원 이상**이 계속 나갑니다.

**소셜 로그인 검증**
카카오는 실서비스로 쓰려면 비즈 앱 전환과 검수가 필요합니다.
구글도 OAuth 동의 화면 검증을 거쳐야 합니다. 둘 다 사업자 정보나 도메인 소유 증명을 요구합니다.
